## 定义

基数排序（Radix Sort）是一种 **非比较** 排序算法：将整数按 **数位（digit）** 拆分，从 **低位到高位**（LSD）依次做稳定排序，最终得到有序序列。

每一轮数位排序本质是键值范围很小的 [计数排序](/dsa/sorting/counting-sort)：本实现基数 `BASE = 10`，每轮对当前位（个位、十位、百位……）在 $[0, 9]$ 上计数、做前缀和，再 **逆序放置**。子过程稳定，整体才 **稳定**。

适用于 **非负整数** 且位数 $d$ 不太大的场景。设 $n$ 为元素个数、$k$ 为最大值的位数（或基数相关参数），时间复杂度为 $O(n \times k)$。

## 过程

工作原理：先求最大值确定要处理多少位，再令 `exp = 1, 10, 100, …` 从 **低位到高位** 逐轮做稳定的按位计数排序。

每轮套路相同：**计数 → 前缀和 → 逆序放置 → 写回**。下面以 `[178, 124, 126, 245, 243, 802, 24, 2]` 为例（最大值 `802`，共三轮），先合并看清各元素的各位 digit 与各轮计数/前缀和，再逐轮说明逆序放置。

### 第一轮：`exp = 1`（个位）— 逆序放置

从输入 **右向左** 扫描，写入 `output[pos]`：

| 扫描 | `digit` | `pos` | 当前 `output` |
| :--- | :--- | :--- | :--- |
| `2` | `2` | `1` | `[_, 2, _, _, _, _, _, _]` |
| `24` | `4` | `4` | `[_, 2, _, _, 24, _, _, _]` |
| `802` | `2` | `0` | `[802, 2, _, _, 24, _, _, _]` |
| `243` | `3` | `2` | `[802, 2, 243, _, 24, _, _, _]` |
| `245` | `5` | `5` | `[802, 2, 243, _, 24, 245, _, _]` |
| `126` | `6` | `6` | `[802, 2, 243, _, 24, 245, 126, _]` |
| `124` | `4` | `3` | `[802, 2, 243, 124, 24, 245, 126, _]` |
| `178` | `8` | `7` | `[802, 2, 243, 124, 24, 245, 126, 178]` |

第一轮结束：`[802, 2, 243, 124, 24, 245, 126, 178]`。`124` 与 `24` 个位同为 `4`，输入时 `124` 在前，输出仍在前，体现稳定。

### 第二轮：`exp = 10`（十位）— 逆序放置

输入为上一轮结果，同样从右向左：

| 扫描 | `digit` | `pos` | 当前 `output` |
| :--- | :--- | :--- | :--- |
| `178` | `7` | `7` | `[_, _, _, _, _, _, _, 178]` |
| `126` | `2` | `4` | `[_, _, _, _, 126, _, _, 178]` |
| `245` | `4` | `6` | `[_, _, _, _, 126, _, 245, 178]` |
| `24` | `2` | `3` | `[_, _, _, 24, 126, _, 245, 178]` |
| `124` | `2` | `2` | `[_, _, 124, 24, 126, _, 245, 178]` |
| `243` | `4` | `5` | `[_, _, 124, 24, 126, 243, 245, 178]` |
| `2` | `0` | `1` | `[_, 2, 124, 24, 126, 243, 245, 178]` |
| `802` | `0` | `0` | `[802, 2, 124, 24, 126, 243, 245, 178]` |

第二轮结束：`[802, 2, 124, 24, 126, 243, 245, 178]`。`124`、`24`、`126` 十位均为 `2`，因个位轮已是 `124(4) → 24(4) → 126(6)`，稳定排序后顺序不变。

### 第三轮：`exp = 100`（百位）— 逆序放置

| 扫描 | `digit` | `pos` | 当前 `output` |
| :--- | :--- | :--- | :--- |
| `178` | `1` | `4` | `[_, _, _, _, 178, _, _, _]` |
| `245` | `2` | `6` | `[_, _, _, _, 178, _, 245, _]` |
| `243` | `2` | `5` | `[_, _, _, _, 178, 243, 245, _]` |
| `126` | `1` | `3` | `[_, _, _, 126, 178, 243, 245, _]` |
| `24` | `0` | `1` | `[_, 24, _, 126, 178, 243, 245, _]` |
| `124` | `1` | `2` | `[_, 24, 124, 126, 178, 243, 245, _]` |
| `2` | `0` | `0` | `[2, 24, 124, 126, 178, 243, 245, _]` |
| `802` | `8` | `7` | `[2, 24, 124, 126, 178, 243, 245, 802]` |

第三轮结束，全部有序。`124`、`126`、`178` 百位均为 `1`，因十位轮已是 `124 → 126 → 178`，稳定排序后顺序不变。

### 为什么是低位优先（LSD）

看完上面的推演，可能有两个疑问：第一轮按个位排完结果「很乱」，为什么最后能全序？为什么不能从百位开始？

比较两个整数时，**高位权重大**——百位不同就能定大小，个位只是最后的 tie-breaker。基数排序走 **相反的路**：从个位开始，逐位向上，每一轮只按 **当前这一位** 做一次稳定排序。

稳定性的作用正在这里：当前位相同时，**保留上一轮已经排好的相对顺序**。

以 `124` 与 `126` 为例：十位都是 `2`，百位都是 `1`——按常规比大小，高位相同，最终要靠个位区分（`4 < 6`）。LSD 正是这样工作的：个位轮先排好 `124 → 126`；十位轮两人十位同为 `2`，顺序不变；百位轮百位同为 `1`，顺序仍不变。三轮下来，`124` 仍在 `126` 前面，**遵循的就是个位轮的排序结果**。

反过来看，高位不同的数不必等低位「传上来」——`126` 与 `178` 百位同为 `1` 但十位 `2 ≠ 7`，十位轮就已分开；`178` 与 `243` 百位 `1 ≠ 2`，百位轮直接定先后。**高位不同由高位决定，高位相同则把问题留给更低的位**——这正是低位优先逐轮叠加的好处。

| 轮次 | 上面例子的结果 | 此时保证了什么 |
| :--- | :--- | :--- |
| 个位 | `[802, 2, 243, 124, 24, 245, 126, 178]` | 个位有序；`124 → 126` 在此确立 |
| 十位 | `[802, 2, 124, 24, 126, 243, 245, 178]` | 十位相同时保留个位结果（`124 → 126` 均十位 `2`）；十位不同则直接分开（如 `126` vs `178`） |
| 百位 | `[2, 24, 124, 126, 178, 243, 245, 802]` | 百位相同时保留前两位结果（`124 → 126` 均百位 `1`）；百位不同则直接分开 → 全序正确 |

若改成 **高位优先**（仍对全数组逐轮计数排序），最后一轮按个位排时 **只看个位**，会把前面排好的大小关系打散。以 `[170, 45, 75, 90]` 为例：百位、十位轮结束后，个位轮会得到 `[170, 90, 45, 75]`——`170` 只因个位为 `0` 被挪到最前。要从高位开始，需要 **MSD 分桶递归**（按位分桶、桶内再排下一位），那是另一套流程，本仓库未实现。

## 性质

### 稳定性

基数排序是 **稳定** 排序算法，但稳定性 **不是** 自动成立的——它依赖每轮子过程 **前缀和（或等价的起始/结束下标）与遍历方向配对正确**。

本实现用 **结束下标 + 逆序放置**：前缀和给出各 digit 的右边界，从右向左扫描时，相同 digit 中靠后的元素先占位，相对顺序与输入一致，低位轮的结果才能带入高位轮。若拿着「结束下标」却从左向右放，会失稳；若改为「起始下标 + 正序放置」，同样可以稳定——两种写法是对偶的。

若某轮子过程不稳定（下标语义与遍历方向不配，或桶内使用快排），整体也不再稳定。

### 时间复杂度

| 情况 | 复杂度 | 说明 |
| :--- | :--- | :--- |
| **最好** | $O(n \times k)$ | 共 $k$ 轮，每轮计数排序 $O(n + \text{BASE})$ |
| **最坏** | $O(n \times k)$ | 与输入分布无关 |
| **平均** | $O(n \times k)$ | 同上 |

$k$ 为最大值的位数；`BASE` 为基数（本实现为 $10$），每轮额外扫 $O(\text{BASE})$ 个桶。

### 空间复杂度

$O(n + \text{BASE})$。需要长度 $n$ 的辅助数组 `output`；每轮计数数组大小为 `BASE`。按惯例归入 **非原地**。

## 代码实现

> 源码: https://github.com/lllllan02/ciu/tree/master/code/radix-sort

### 基础写法

本仓库实现。LSD 基数排序，`BASE = 10`，每轮对当前位做稳定计数排序：

```c
#define BASE 10

static int bucket_index(int value, int exp) {
    return (value / exp) % BASE;
}

void radix_sort(int* arr, int len) {
    if (len <= 1) return;

    int max = arr[0];
    for (int i = 1; i < len; i++) {
        if (arr[i] > max) max = arr[i];
    }

    int exp = 1;
    int* output = malloc(len * sizeof(int));
    if (!output) return;

    while (max / exp > 0) {
        int buckets[BASE] = {0};

        for (int i = 0; i < len; i++) {
            buckets[bucket_index(arr[i], exp)]++;
        }

        for (int i = 1; i < BASE; i++) {
            buckets[i] += buckets[i - 1];
        }

        for (int i = len - 1; i >= 0; i--) {
            int index = bucket_index(arr[i], exp);
            int pos = --buckets[index];
            output[pos] = arr[i];
        }

        for (int i = 0; i < len; i++) {
            arr[i] = output[i];
        }

        exp *= BASE;
    }

    free(output);
}
```

### 优化写法

**起始下标 + 正序放置**：与基础写法等价，均稳定；只换单轮计数排序的写法，**数位顺序仍是 LSD**：

```c
int start[BASE] = {0};
for (int i = 1; i < BASE; i++) {
    start[i] = start[i - 1] + buckets[i - 1];  // buckets 为原始计数
}
for (int i = 0; i < len; i++) {
    int index = bucket_index(arr[i], exp);
    output[start[index]++] = arr[i];
}
```

**MSD（高位优先）递归分桶**：先按最高位划分，桶内递归处理下一位；不等长位数时更自然，但实现较复杂，且需处理空桶与边界。这才是真正的「高位优先」，不能靠把逆序改成正序得到。

**增大 `BASE`**（如 $256$）：减少轮数，但每轮计数数组变大，需权衡 $k$ 与 $\text{BASE}$ 的乘积。

处理 **负数** 时，可先平移全体元素到非负范围，排序后再移回。
